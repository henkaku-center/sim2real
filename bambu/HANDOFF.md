## 4. 主な設計判断と理由

- **球面の中心を重心の真上に置く。** 硬い床の上では凸包しか床に触れない。静止できるのは「重心から下ろした垂線の足が面の内側に
  入る面」だけ。球の中心が重心より上なら、腹側から頂点に向かって重心からの距離が単調に増え、極小（止まれる姿勢）は腹ばい
  だけになる。
- **甲羅が大きい理由は膝サーボの取付タブ。** 上流STEPではタブが腹面より 5 mm 下に出ていて、横転・前後転の支点になる。
  縁を Z = 33（水平にした下腿より上）で外側へ張り出さないと、その支点で止まる。
- **畳み姿勢は股 q = 90°・膝 q = −90°。** 横倒しのとき、この下腿の掃引面は床と平行になるので、脚で床を押さない。
  股 0° で畳むと床を押してしまう。甲羅には下腿が通るスロットを4本あけている。
- **穴の大きさは e·sin(θ − 重心誤差角) − 1.5 mm 以下。** 床が穴をまたぐと平らな小面になり、それが機体を支えてはいけない。
  天頂から約27°以内は穴なし。**天頂に平らな面・ネジ・サポート痕を作ってはいけない**（仰向けで安定してしまう）。
- **質量と形は反復で一致させる。** 甲羅の自重で重心が上がるので、形→質量→重心→球の中心 を固定点まで回す（2〜3回で収束）。
- **一体版で縦ネジにした理由。** 2部品版の横ネジは、ドームが被さると締められない。上蓋の内幅は約31 mmで、内側からの横ネジも
  無理。上蓋を外して内側から上向きに締める形にした。ネジ位置の上蓋天面は 1.3 mm 厚で、真下は空いていることを確認済み。

## 5.4 呼吸するドーム Ø100（2026-11-05 追加）

- 依頼：直径10 cmの試作で、3 mm骨格＋1 mm皮膚（穴なし）にする。呼吸しているように見せたい（ソフトロボティクス風の膜と口）。
  研究構想「浸透する身体」（環境 → 生理状態 → 外から見える症状）の最初の出力器官という位置づけ。
- 実装は自己復帰甲羅とは独立：`breath_params.json`、`scripts/build_breath.py`（FreeCAD）、`scripts/breath.py`（生成・検証・プレビュー）。
  出力は `stl/breath/`、手順は [`BREATH.md`](BREATH.md)。`design.py` や `params.json` には触っていない。
- 構成：V3の取り外し式の蓋に台座を蓋の裏からネジ留めし、その上に床板・肺カプセル（天頂、膜Ø36）・口カプセル（正面、切れ目入りの唇）・ドームを載せる。
  空気はチューブで外から送る。Ø100ではポンプがドーム内に収まらないため。
- 検証：全7部品が水密。ドームとカプセルのすき間 ≥ 1.88 mm、台座と耳 0.86 mm、蓋へのめり込み 0。
  脚は歩行範囲と全モーションで ≥ 23 mm（上流の脚メッシュを V3 の股関節軸とサーボ取付面 Z = 4.97 へ平行移動して照合）。
- 未確認：蓋の裏に出るネジ頭と内部配線の干渉、空気漏れ、唇の切れ目の調整。このドームは自己復帰しない。
- **元の要件との関係**：R6〜R8・R11〜R14 を満たさない。天頂の窓は REQUIREMENTS C2 に反する。机上の試作（膜・口・空気回路の確認）に限定する（E5）。
  本番に統合するなら、窓を θ ≥ 60° の側面へ移し（半径 14 mm まで）、転倒時に吐ききる制御を加え（E1・E2）、質量を再計算する（E3）。

    2本の細い線で刷る想定。実物で確認が必要（NEEDS-HARDWARE）。
- 別の作業（LEDらせん版）の変更で、`design.make_job` の `perforation` に肉厚 `t` が渡らなくなっていた
  （らせん版以外がすべて止まる不具合）。両方に渡すよう修正し、元の版・s3-wide版・v3版の体積が変わらないことを確認した。
- 前提：フレームはV3キット。質量は推定（PLA 1.2 g/cm³。PETGなら約6 %重いが、判定には余裕がある）。

## 5.5 V3頭アーム版（2026-11-13、最新・印刷用）

- 依頼の流れ：①甲羅・クラウン・ふたを一体にしたい、クラウンではなく棒（キノコ形）でよい、刷りにくい形は避けたい
  → ②フレームにマウントを付けて甲羅を取り付けたら？ → ③サポートありでよい、失敗しにくく強度が出る形、フレームごと作り直してもよい。
- **甲羅＋棒＋ふたの一体は、サポートなしでは刷れない**：甲羅は縁（z 34.5）をベッドに置く必要があり、ふた（z 66〜70）がその内側で宙に浮く。
- 試行1：キノコ形（`params-v3mushroom.json`、`stl/v3mushroom/`、variant `v3-mushroom`）。甲羅＋「棒＋ふた」の2部品。棒先端の割りピンが
  天頂の穴を通ってスナップする。**不採用**：割りピンの4 mmのすき間が天頂を横切って平らな稜線になり、MuJoCoで完全仰向けのまま止まった
  （重心ずらしの静的判定も深さ0.28 mmで不合格）。柄＋ふたは27.8 gで、重心も1.1 mm上がった。fit_check は未完了のまま打ち切り。
- 試行2：フレームから生やす案。フレーム中央の左右の切り欠きをサーボのリボンが通っていて（y≈35で縦に上がる）、股サーボの内側の耳ネジ（x = ±9）もある。
  さらにフレームは基板側を下にして刷るので、上向きの柱を生やすとサポートだらけになる。そのため**頭カバーから生やす**ことにした
  （頭は四隅のネジでフレームに固定）。
- 採用：`params-v3headarms.json`、variant `v3-headarms`。脚の掃引（歩行範囲、股 −10°、畳み、全モーション）を2 mmのボクセルで調べ、
  |x| ≤ 10 mm の左右の通り道は z ≥ 26 で脚が来ないことを確認してから、そこにアームを通した。
  - 1回目は歩行範囲で4.0 mm（基準6 mm）：付け根のブロックの角（x 10.9）に前脚の大腿。幅±10 → ±6.5 mm に変更。
  - 2回目は5.5 mm：股 −10°で大腿が x≈10.4・z ≤ 42 まで来る。アームの細い部分を z 44〜56 に上げて解決（7 mm以上）。
- 結果は README の「V3頭アーム版」。analyze・fit_check ともに全項目合格。
- コード：`design.v3_headarms_job`、`build_shell.head_arms`（`head-mount` = 印刷用の頭全体、`head-arms` = 質量計算用のアームだけ）、
  `fit_check.headarms`、`make_plates.py --variant v3-headarms`。キノコ形の `v3_stem_job`・`stem_lid`・`fit_check.mushroom` は記録として残してある。

## 5.6 V3頭アーム版の甲羅を厚く・膜付きに（2026-11-17）

- `plate1-shell-dome.3mf`（肉厚1.3 mm）をPLAで刷ったらスパゲッティになった。ツリーサポート（スライサーで有効）は
  最後まできれいに立ち、壊れたのは甲羅の壁だけ。積層ピッチ・壁ループ・失敗した高さは記録なし。
- STLの輪切り：z 0〜約40 mmは膝スロット（幅約40 mm×4）で甲羅が**つながっていない4枚の花びら**、z 25〜65 mmは
  一周のうち肉が43〜60 %しかない桟（幅4 mm×厚さ1.3 mm）のかご。内側に傾いた細い片持ちが、ノズルに押されて
  しなったと見ている（クラウンの柱と同じ失敗）。
- 対策：
  - `shell.thickness` 1.3 → 1.6、`perforation.min_web` 4 → 5（穴127 → 126個、甲羅64.7 → 82.5 g）。
    2.0／6は重心が8.5 mm上がり、アームの受けが甲羅の縁の外に出た。1.8／5（94.5 g）は重心ずらしの止まり方が
    0.227 mm（基準0.2）で不合格。1.7／5は0.163 mmで合格だが、重心ずらしなしでも浅い止まり方（0.03 mm）が出た。
    1.6／5は最大0.109 mmで、重心ずらしなしの浅い止まり方もない。
  - `shell.print_ties.t` = 0.8：膝スロットを壁の厚さの真ん中で膜（厚さ0.8 mm）でふさいだ `shell-dome-print.stl`
    （`build_shell.slot_ties`）。スロットの切り抜きは `build_shell.slot_tools` に分けた。膜は約5.9 cm³。
    プレート1はこれを使う（`make_plates.py`）。`fit_check` は膜付きの印刷性も見る（13項目すべて合格）。
- 判定：analyze 全項目合格（落下122/122、復帰8/8、重心ずらし落下100 %）。畳まない場合の復帰は6/8 → 5/8。
- 未確認（NEEDS-HARDWARE）：膜の切り取りやすさと切り口の仕上がり、1.6 mmで本当にしならないか、実際の甲羅の質量。
- 元の出力（1.3 mm版）は作業中に /tmp に退避しただけで、リポジトリには残していない。

## 5.7 バヨネットのかかりを深く・縁の帯を厚く（2026-11-26）

- 実物（1.6 mm版）の所見：バヨネットがちゃんと掛からない。甲羅の剛性が足りない。甲羅がアームに対して直径で約1 cm大きい。
- 確認：`plate1-shell-dome.3mf` は設計どおり直径188 mm（3MFに拡大・収縮補正なし）。つまり設計上の寸法の問題ではなく、
  膝スロットで切り離された左右の花びら（肉厚1.6 mm）が開くなどして、爪（溝へのかかりは半径方向2.9 mm）が届かなかったと見ている。
- 甲羅を小さくする案は不可：R 94 → 89 で横向きの安定姿勢（傾き66°、深さ0.23 mm）が残り、歩行範囲のすき間も5.83 mm（基準6）。
  R 91・92 も重心ずらしの止まり方が0.34・0.24 mm（基準0.2）で不合格。R 94 が自己復帰の下限に近い。
- 対策（R 94 のまま）：
  - `shell.rim_band`（t 2.6、z_top 50）：縁から z 50 までだけ壁を内側へ厚くした（上端は45°で1.6 mmに戻す。rim-down で刷れる）。
    `build_shell.dome` と `design.v3_headarms_job`（縁の内径）が対応。低い位置の質量なので重心ずらしの止まり方は0.119 mm（従来0.109）。
  - アーム先端の溝を3.6 mm内側へ（`y_back` 76.4、`y_face` 80.0）、上の張り出し `ledge_out` 3.4 → 6.0、`y_out` 89.6 → 88.8。
    爪の溝へのかかりは半径方向2.9 → 5.5 mm。
  - 全体の肉厚1.7 mm＋帯も合格したが、重心ずらしなしでも浅い止まり方（0.036 mm）が出るので1.6 mmのまま。
- 判定：analyze 全項目合格、fit_check 13項目合格。甲羅とアームの両方が変わったので **plate1 と plate2 の両方を刷り直す**。
- 旧出力（R94・1.6 mm・旧アーム）と、ユーザーがスライサーで保存した旧 `plate1-shell-dome.3mf` は
  `bambu/_backup/v3headarms-R94-t1.6-20261126/` に退避した。試作は `bambu/_try/`。
- 未確認（NEEDS-HARDWARE）：帯で花びらの開きが本当に収まるか、ひねりの固さ（デテントの干渉は0.74 mm）。
- 1回で刷る用に `plate-dome-with-head.3mf` を追加（`make_plates.NEST_HEAD_DEG`）。頭を甲羅の中のベッドに置き、65°回して
  アーム先端を横の爪と膝スロットの間に向ける（甲羅の内壁まで2.6 mm。回さないと1.2 mm）。甲羅のブリムは外側だけ、
  頭のアーム下にツリーサポート。刷り終えたら甲羅を真上に持ち上げて外す（アーム先端88.8 mm < 縁の内径89.65 mm、爪とは重ならない）。
  ただし頭のサポートが崩れると甲羅を巻き込む（2026-11-12のクラウンと同じ形の失敗）ので、確実さを優先するなら別々に刷る。
- まとめ刷りをサポート有効でスライスすると「G-codeパスの競合（head-mount↔shell-dome）」が出た。Bambu Studio CLIで再現し、
  頭だけ刷った G-code から原因を特定：頭のツリーサポートの根元が半径93.7 mmまで広がり、甲羅の縁の壁（内径89.65）に食い込む。
  甲羅のサポートを入れても競合（内側のツリーが頭とぶつかる）。通る設定：甲羅はサポートなし（形はサポート不要、
  25°未満は天頂の9 mm²だけ）・ブリム外側のみ、頭はノーマル(auto)＋snug、`raft_first_layer_expansion` 0
  （ノーマルでも1層目の土台が2 mm広がって甲羅の縁に触れる）。頭の経路と甲羅の表面は最短1.35 mm（線の中心）。
  この設定入りのプロジェクトを `plate-dome-with-head-bambu.3mf` として出力（`scripts/make_bambu_project.py`、
  設定はユーザーが保存した P1S・0.08 mm・PLA の `bambu/slicer/p1s-0.08mm-pla-tree.config`）。CLIでのスライス：競合なし、約10.3時間。

## 6. 再生成と検証（所要時間はこの macOS 機での実測）

```sh
git clone --depth 1 https://github.com/dorianborian/sesame-robot.git bambu/vendor/sesame-robot   # 初回のみ
/Applications/FreeCAD.app/Contents/Resources/bin/python -I bambu/scripts/extract_upstream.py \
    bambu/vendor/sesame-robot/hardware/cad/Sesame-ESP32-v122.step bambu/build/upstream            # 約15 s
uv run python -I bambu/scripts/design.py      # 約18 s（FreeCAD を呼ぶ。両方式のSTLを出力）
uv run python -I bambu/scripts/analyze.py     # 約90 s。不合格があれば終了コード 1
uv run python -I bambu/scripts/previews.py    # プレビューPNG
uv run python -I bambu/scripts/size_sweep.py  # 任意、約7分
```

| スクリプト | 役割 |
|---|---|
| `extract_upstream.py` | （FreeCAD Python）STEP → 部品ごとのSTL＋`parts.json`（スプライン軸を含む） |
| `sesame_model.py` | 部品の分類（胴/大腿/下腿）、質量の割り当て、脚の姿勢（manifest の q 規約）、重心 |
| `design.py` | 穴・スロット・サドルを計算し、ジョブJSONを書いて `build_shell.py` を呼ぶ。質量と重心を反復 |
| `build_shell.py` | （FreeCAD Python）ドーム・マウント・一体版・治具を B-rep で作り、STEP/STL を出力 |
| `stability.py` | 凸包の面ごとの平衡判定（余裕と深さ）、盆地 |
| `analyze.py` | 静的安定・重心誤差・保護・FCL によるすき間・MuJoCo をまとめて `report.json` を書く |
| `sim_check.py` | MuJoCo の剛体落下と、関節付き（トルク制限サーボ）の復帰シーケンス |
| `render.py` / `previews.py` | MuJoCo のオフスクリーン描画 |
| `size_sweep.py` | 半径 R・中心の高さ e と性能のトレードオフ |

座標系：mm、X前・Y左・Z上、Z = 0 は底カバーの下面。上流STEPからの変換は (X, Y, Z) = (26 − ux, uz − 2.38, uy + 1.0)。
関節は manifest の内部角 q（firmware_deg − 90）×sign を使う。STEP は q_hip = 45°、q_knee = 90° の立ち姿勢で描かれている。

## 7. ハマりどころ（次の人が同じ所で詰まらないように）

- `python -I` は `PYTHONPATH` を無視する。FreeCAD のモジュールはスクリプト内で `sys.path.append` している。
- FreeCAD の `cut` は Compound を返すことがある。単一ソリッドを確認してから `Solids[0]` を取る。
- scipy の `ConvexHull.simplices` は向きが揃っていない。三角形の内外判定は向きに依存しない方法で行う。
- `Top-Cover-Enclosed-v117.stl` は水密でない。断面ではなくレイキャストで寸法を測る（`profile_yz` はそうして得た値）。
  上蓋の耳の根元は X = 17.25 より後ろまで広がっているので、サドルの前端は 2.25 mm 手前で止めている。
- STL の細かい三角形分割は、天頂付近に深さ 0.0003 mm 程度の「偽の安定面」を作る。`micro`（深さ < 0.02 mm）として除外している。
- 盆地計算をサンプリングで行うと、凸包の長い稜線（前後の膝タブが一直線に並ぶ）で止まって偽の極小が出る。
  支持関数を 2 mm 幅の log-sum-exp で平滑化して回避した。真偽は面解析（厳密）で判断すること。
- MuJoCo は各メッシュを凸包として扱う（ドームは中身の詰まった塊になる）。脚と甲羅の衝突はシミュレーション内では見ておらず、
  FCL による幾何チェックで別に確認している。
- サドル下端は印刷時にベッドから 14 mm 浮く。サドルの空洞はサポートを Block しないと嵌合面が荒れる。

## 8. 未検証・仮定（NEEDS-HARDWARE）

- 質量はすべて推定（サーボ 13.4 g、電池 40 g、PLA の実効密度 0.95 g/cm³、配線など 12 g）。形状は上流 ESP32 v122（SG90 形状）。
- manifest の関節の符号は「assumed」。畳み姿勢は、甲羅を外して1関節ずつ低速で確認すること。
- 転倒検知用のIMUは未搭載（現状は手動コマンドでしか試験できない）。
- サーボ負荷（+59 g、重心上昇）での歩行性能は未評価。LM2596 の電圧降下も要観察。
- 完全仰向けは理論上は不安定な釣り合い。シミュレーションでは数値誤差で倒れたが、実機では外乱が要るかもしれない。
  止まったら制約として記録すること。
- 甲羅を付けていると dance / point / cute で脚が甲羅に当たる。
