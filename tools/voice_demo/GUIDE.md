# Guide brief: “AI is not magic” robot

**Hold the button, say one short request, then release.** Wait while the console
shows what it heard and what it will play. The robot performs one finite
sequence and releases its outputs afterwards. Press Escape / Outputs OFF to
cancel. It does not listen continuously.

## Good prompts

- “Do a bow.” / 「お辞儀して」 — a stock bow.
- “Say hello to the audience.” / 「みんなに挨拶して」 — a face and wave;
  the robot does not speak aloud.
- “Dance”, “swim”, “shrug”, “look cute” — named stock gestures.
- “Move like a snake” / 「蛇みたいに動いて」 — a custom pose sequence.
- With the real provider: describe a short movement or ask for a named facial
  expression, such as happy, sad, surprised or sleepy. Creative interpretation
  is variable; “snake-like” is an interpretation, not a learned snake controller.

Keep one idea in each request. Complicated requests may be declined if they
cannot fit the finite plan or the robot's joint travel. Read the console reason
and try a simpler description. A completed serial command is not proof that the
robot physically performed it.

## What this version cannot do

- Draw a custom picture or accept `face_bitmap`; the firmware supports named faces only.
- Talk, listen to follow-up speech while moving, see the audience, recognize
  people, navigate around objects, or execute generated code.
- Play `walk` or `point` in this demo: those stock sequences contain a hip
  target beyond the fitted-travel limits. Other named motions remain available.
- Make claims about balance, power capacity or collision-free real movement
  based on a successful software simulation.

## When the network fails

The console reports the failure and outputs remain off. **Local keys still work:**

| Key | Action |
|---|---|
| 1 | Bow |
| 2 | Wave |
| 3 | Rest |
| Escape | Cancel and turn outputs off |

A local key overrides a pending server answer. A late answer will not suddenly
start a second movement. A downloaded plan plays locally, with its heartbeat
generated by the Pi. If the serial device disappears, the relay cannot confirm
OFF; its heartbeat stops and the firmware watchdog is expected to release it.
Do not describe this as measured until tested on the installation hardware.

## Explain the demonstration

“The server turns speech into text and proposes a small plan. The Pi checks the
plan and performs it locally. The robot knows a library of gestures and can also
accept a sequence of joint positions. It is not magic or unrestricted control.”

If running **fake provider** mode, say so: text examples are deterministic, and
every WAV uses the fixed “do a bow” transcript. That mode tests the software loop;
it is not speech recognition. Real-provider mode sends the recording to **Deepgram
through Kotoleaf**, then the transcript to **Claude** for a plan. Console
logs include transcripts. Kotoleaf selects Nova-3 English/Japanese code-switching;
Claude itself does not transcribe the recording.

## Operator configuration

The server defaults to `VOICE_PROVIDER=claude` with Deepgram speech through Kotoleaf.
Set `VOICE_CLAUDE_BASE_URL`, `VOICE_CLAUDE_TOKEN`, and `VOICE_PLAN_MODEL` in the
server's private environment. For the test Worker, use its origin and access
token. To move to an Anthropic Console key, change the URL to
`https://api.anthropic.com`, replace the token with the Console key, select an
available model, and restart the server. Nothing changes on the Pi.

Set `VOICE_STT_TOKEN` to the Kotoleaf access token; `VOICE_STT_URL` defaults to
`https://kotoleaf.wandering-sky-fcce.workers.dev`. Full configuration is in
[README.md](README.md#configure-claude-and-deepgram). Fake mode must be selected
explicitly. A missing key is an error, not a silent switch to fake mode.

Claude gets one correction attempt if its proposed plan is invalid or it omits
the tool call. After that the console shows refusal notes and no motion starts.
Live gateway text checks now work, with typical stock plans returned in about
2.5 seconds. A custom snake request took about 7.4 seconds including correction.
One incorrect face substitution was found and the prompt clarified; the
unsupported eye request then correctly refused in English and Japanese.
Live audio recognition and physical motion remain unverified. See
[VALIDATION.md](VALIDATION.md).
